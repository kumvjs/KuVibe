# Philosophy

KuVibe separates user intent from engineering process. A user should explain the outcome they need; the coding agent should retrieve context, detect ambiguity, select useful engineering perspectives, define acceptance, implement, verify, and preserve knowledge.

Its central rule is “inspect first, ask only when material.” Existing project evidence answers many apparent questions. When an answer would change business rules, permissions, data, contracts, security, significant UI, compatibility, irreversible actions, or acceptance, the agent asks a small, concrete question.

Workflow depth follows risk and complexity. Tiny changes remain tiny; cross-module and high-risk work gains explicit artifacts and review.

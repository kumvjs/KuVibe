# Requirement Workflow

1. Retrieve `.agents/project.md`, relevant context, module docs, notes, and source.
2. Normalize the goal, users, behavior, constraints, exclusions, and acceptance signals.
3. Mark completeness as `complete`, `assumable`, or `incomplete`.
4. Record low-risk assumptions. Ask 1–5 focused questions only when answers materially change behavior, boundaries, state, permissions, data, API, security, UI, compatibility, irreversible actions, or acceptance.
5. Classify task, scope, risk, and complexity (Level 0–3).
6. Select only useful perspectives such as architecture, API, UI, security, testing, acceptance, and documentation.
7. For Level 2–3 work, persist requirement, analysis, acceptance, and plan artifacts under `.agents/notes/active/<slug>/` before implementation.

Inspect first. Ask only when material.

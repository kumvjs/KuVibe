# Documentation Workflow

Before completion, classify impact on product behavior, workflows, data model, API/CLI, UI, operations, and architecture. Update relevant `docs/` pages when current truth changed; otherwise explicitly record N/A in the final verification or engineering note.

Write a timestamped implemented note for new capabilities, business/protocol rules, important bug causes, schema changes, major refactors, architecture, security, performance, or migrations. Notes contain durable context and decisions, not scratch reasoning. Consolidate and remove the completed active directory.
